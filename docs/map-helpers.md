# The file map — the helpers every task imports

Filesystem and token accounting, the prompt helpers, the manifest helpers, the shared guards, the hook runner, and the source bundle.

Part of the ai-client documentation; the entry point is [AGENTS.md](../AGENTS.md).

## The file map — the helpers every task imports
| Path | Role |
|---|---|
| `utils/fs.js` | Filesystem helpers: `fileExists`, `assertWrote` (rejects missing, empty, AND stub content), `isPlaceholderContent` (detects the scaffold-stub marker), `assertWroteWithFallback` (chat-reply fallback — treats an empty/stub file as missing so it can be overwritten; returns true ONLY when a file was actually missing, and callers MUST gate their recovery turn on that value; the fallback is GATED by `looksLikeArtifact` — it writes only when ONE file is missing and the reply actually looks like the document it should hold, see gotcha 58), `looksLikeArtifact` (the plausibility gate: a headed Markdown document of at least `FALLBACK_MIN_CONTENT_CHARS` characters, or a table), `hasDocumentShape` (the shape half: a Markdown heading or a table), `FALLBACK_MIN_CONTENT_CHARS` (`AGENT_RECOVERY_MIN_CHARS`, default 1000; `0` disables the gate), `assertRealOutput` (the hard stop after a recovery turn: missing/empty/stub = error), `hasRealOutput` (the idempotency skip-check — file exists AND is not empty/stub), `isPublishableArtifact` (the STRICTER rule for the four series-root copies: real AND has the shape of the document it claims to be, with a warning instead of a silent skip — gotcha 50), `inlineReferenceMessage` (inline a cumulative reference with optional truncation), `writeProvenanceSidecar` (writes the `<copy>.provenance.json` sidecar next to a series-root artifact copy), `fingerprintFiles` (a content hash of the named files — `path:length:sha256` joined, an unreadable file fingerprints as `missing` so a read error cannot masquerade as "nothing changed"; the QA loop takes it before and after a feedback pass and stops when the two match, because a pass that rewrote nothing is not an iteration — see docs/architecture.md "QA loop" and gotcha 65), **`stageSourceFile` (put a source where a volume folder expects it WITHOUT a second copy — a relative shortcut to the original, falling back to a copy where this filesystem cannot link; the destination is inspected with `lstat` first so a broken shortcut is refused instead of written through, and the no-clobber content comparison still runs — see gotcha 77)**, **`shortcutTarget` (where a shortcut points and whether it resolves — the two halves a "source file not found" error needs once a staged book is a shortcut)**, `wipeAttemptOutputs` (removes ONLY the named files — plus an optional glob for a mode's per-chapter strays — before the whole→chunked fallback re-runs a volume; it never walks the folder and never touches the source bundle). |
| `utils/tokens.js` | **The one place the pipeline's token estimate lives.** `estimateTokens` / `estimateMix` (calibrated coefficients: `DEFAULT_CJK_WEIGHT` 0.69 per CJK char, `DEFAULT_OTHER_WEIGHT` 0.25 per other char, `DEFAULT_TEMPLATE_OVERHEAD` 52 per REQUEST — billed once, in `tokenBudgetFor`, never per block), `scriptMixOf` (a text's CJK-vs-everything else character counts: the half that belongs to the TEXT, measured rather than implied by a language name), `tokenEstimateMargin` (`TOKEN_ESTIMATE_MARGIN`, default 1.15 — the explicit guarantee that the estimate is an over-estimate, replacing the accidental 1.45× the old coefficients carried; sized from the measurement that a calibrated base estimate lands up to ~5% UNDER one volume's own count), `deriveCoefficients` (pure: solve the coefficients from ONE measured request — a CJK-heavy sample solves the CJK weight and keeps the fitted Latin one, a Latin-only sample scales both), the per-endpoint calibration cache (`.token-calibration.json`, keyed on `baseUrl|model`, age-guarded by `TOKEN_CALIBRATION_MAX_AGE_HOURS` because a shared-port setup gives every container the same alias — see gotcha 22), `ensureTokenCalibration` (stage-start: reuse the cache, else probe once against the volume's own text, else fall back to the built-in coefficients — FAIL-SOFT, token accounting must never be the reason a run dies), `tokenBudgetFor` (the pure budget arithmetic), `globalEndpoint` / `budgetFor` (what window and reply reserve a stage budgets against), `chunkSafetyFraction` (`SOURCE_CHUNK_SAFETY_FRACTION` — now ONE knob for both size decisions, the whole-installment one and the chapter-part one; `utils/source.js` re-exports it), `artifactGrowthFactor` (`ARTIFACT_GROWTH_FACTOR` — how much a cumulative reference is expected to grow per volume) and `answerRoom` (the ANSWER side of the size question: the expected output × the estimate margin vs the output cap the server actually enforces — see docs/architecture.md "Processing mode"), `describeCoefficients`. **A token count belongs to a (text, model) pair**, which is why the bundle persists the script MIX and not a token count (see docs/architecture.md, gotcha 54). |
| `utils/agents.js` | The shared malformed-tool-call guard: `emittedToolCallAsText` (a turn made no real tool calls but its text contains `tool_call` / `<function=` — the intermittent local-endpoint failure) and `assertRealToolCalls(result, who, volumeLabel?)` (throws a diagnostic error for it instead of letting the stale-file write check mask the no-op turn). Used by every file-writing task (glossary, character-voice, style-guide, jump-in-wiki, consistency-audit, intake) — previously each carried its own copy. Plus **`turnShapeOf(result)`** — the honest record of a turn that has NO step cap: `{chunks, toolCalls, offloads, offloadedTokens, compactions, endedAs}`, built from what the harness actually did rather than from a limit the role does not have. `endedAs` keeps the harness's own word for how the turn ended, verbatim, so a record cannot soften "stopped" into "finished". A diagnosis record and a patch record both carry it (`turnShape`), and `fix.js` prints it. |
| `utils/prompt.js` | Prompt/verdict helpers: `transformUserPrompt`, `isPassingVerdict` (legacy binary verdict — kept for compatibility, no longer used in the acceptance path), `parseAcceptanceReply` (parses the acceptance one-shot reply — the JSON `{"score", "band", "note"}` contract first, then the legacy `parseAcceptanceScore` integer forms as a fallback; `null` = unparseable = failed check), `parseAcceptanceScore` (legacy 0–100 integer parser — the fallback half of `parseAcceptanceReply`), **the three agent step caps** — `validatorMaxStepsFor(sourceBytes)` (`max(40, 2·ceil(bytes/32KB) + 24)`), `authorMaxStepsFor(artifactSizeBytes, sourceBytes)` (a cumulative-artifact author/feedback turn reads the artifact it amends AND the text it amends from; a flat 40 is where 17 of the live run's 25 step-cap warnings came from, and the flat 30 the character-voice and style-guide stages carried is where their zero-write 46-tool-call feedback turn came from), `findingsMergeMaxStepsFor(segmentCount, artifactSizeBytes)` (the chunked findings-merge agent reads one partial per chapter plus the artifact it audits; a flat 20 lost a whole validation round on a 10-chapter volume) — all three follow what the agent must READ, because a cap that is too low throws away work already paid for (gotcha 64); `writePromptDump`, and **`selectSectionsByRelevance`** — the shared truncator for cumulative, section-organised references. It keeps the sections that MATTER to the text being processed (a heading, or a quoted source-language span, that occurs in it) and drops the rest, instead of "the last N sections" / "the first N characters", which for a cumulative document means the volume-1 main cast and the honorific rules are the first things thrown away. Used by `truncateGlossary` (via its own table-aware variant), `truncateVoiceRef`, `truncateStyleGuide`, and `loadVolumeReferences` (with `maxChars`). Without a source text it keeps the legacy window and its note SAYS so. |
| `utils/manifest.js` | JSON/manifest helpers: `extractJsonObject`, `installmentNumberFromDir` (legacy), `normalizeInstallmentNumber` ("1"/1/"007" → "01"), `sanitizeFolderName` (an agent-chosen folder name is validated, never rewritten: no separators, no `..`, no absolute paths, no Windows-illegal characters, source-language text kept), `filterVolumesByInstallment` (the `--volume NN` lookup — by the manifest's installment number, or an exact folder name). |
| `utils/source.js` | Source-bundle helpers: `resolveSourceBundle` (normalizes a volume's source into a `SourceBundle`; plain-text passes through as-is, `.epub` is extracted once and cached; every bundle carries a `sourceFingerprint` — `sha256OfFile(originalPath)` for plain text, the cache `sha256` for epub — used by the source-staleness detection, see docs/architecture.md, and a `scriptMix` for the whole installment plus one per segment — the character counts the token estimate is computed from, see `utils/tokens.js`), **`planProcessingMode` (the whole-installment vs chapter-by-chapter decision, in tokens: `source + injected references + instructions <= safetyFraction × roleWindow − reply reserve`, returning the mode plus the numbers and the basis it used) and `decideProcessingMode` (the same decision end to end for one volume of one stage: calibrate the estimate against the model this stage is about to run on, measure the reference material it injects, decide, LOG the numbers, and separately report the ANSWER it expects to have to write — the previous volume's artifact × `artifactGrowthFactor` against the output cap, via `tokens.answerRoom`; reported, never used to flip the mode, because a cumulative reference is still written whole at the final chapter)** — `shouldProcessChunked` is now the documented FALLBACK that rule uses when the token rule is unavailable (a bundle cached before schema 6, or a stage with no known window), `splitPlainTextSegments` (paragraph-aware, lossless split of an oversized plain-text source) + `materializeTextParts` (writes/caches the part files by source fingerprint), **`openEpub` (the single shared epub container reader: catalog card — title/creator/language/publisher/identifier plus the Calibre or EPUB3 series marker — the manifest, the spine, the readable sections and their nav titles, `navEntries` (the same nav links IN DOCUMENT ORDER, each with `inToc` and its declared `epub:type` — the book's own declaration of where its sections begin), and `payload` — the archive's uncompressed text bytes vs its other bytes, read off the zip central directory without decompressing an image; parses the OPF as XML)**, `readEpubSection` (bounded plain-text slice of one section), `htmlToPlainText`, `scriptCounts` (kana/hangul/Han/latin counts — evidence for the intake agent, not a decision), `extractEpubToBundle` (built on `openEpub`; XHTML → Markdown, then **sections are grouped into chapters by the book's own contents list** — `groupSpineIntoChapters` + `classifySectionGroup` + `titleOfUnnamedSection` + `stripRepeatedHeading` — see docs/architecture.md "Source bundle" and gotcha 52; per-chapter files, interludes, epilogue, images), `assignSegmentIds`, `classifyTitle`, `xhtmlToMarkdown`, `sourceMaterialLine`, `sourceSegmentListLine`, `chapterSegmentNote`, `chapterContextBlock`, `isEpubPath`, `normalizeZipPath`, `sha256OfFile`, `plainTextTitle` (a plain-text source's own declared first-line title, marked `syntheticTitle: true` when there is none). **Extraction honesty:** `extractEpubToBundle` logs the spine accounting (how many items it was offered, how many it could read, and WHICH it skipped), logs the packaging it skipped and WHY (each entry also persisted in `bundle.packaging`), warns when the contents list omitted a section that holds real text (it is kept as a chapter, titled from what the page prints, or `Untitled section N` + `syntheticTitle: true` when it prints none), warns when the packaging it skipped is more than 10% of the chapters' text (the tell that a real chapter was cut), flags every segment with `bodyChars` and `empty` (under `SOURCE_EMPTY_SEGMENT_CHARS`, default 200 — a blank page, an image-only page, a section whose text lives in a structure the converter does not map), and warns when the per-chapter files and the whole-installment file disagree in length. A chapter that is empty IN THE SOURCE is a hole in the book, and it is reported at extraction instead of surfacing later as a mysterious translation failure. `BUNDLE_SCHEMA_VERSION` (6) is part of the extraction cache key — renaming the id scheme or changing the shape bumps it and forces a clean re-extraction (5 = chapters come from the contents list, not one per spine page; 6 = every bundle records its SCRIPT MIX, whole and per chapter, so a token estimate can be recomputed for a different model without re-reading the book). All nine task modules resolve their source through `resolveSourceBundle` at the choke point; the intake agent's epub tools go through `openEpub`. |
| `utils/hooks.js` | Per-machine pipeline-hook runner (git-style, entirely optional). Discovers `hooks/pre-<task>` / `post-<task>` (and `pre-/post-pipeline`) and `exec`s each as an executable with `AI_CLIENT_*` env vars; skips when the file is absent, under `--dry-run`, or not executable. Applied via `withHooks()` in gulpfile.js. `SUPPORT_TASKS` (`manager`, `autopilot`) are **pseudo-steps**: hook names that are not gulp tasks and are deliberately kept out of `TASKS`, so `pre-manager` / `post-manager` / `pre-autopilot` / `post-autopilot` exist without pretending the support roles are pipeline stages. `runTurnWithHooks(task, turnFn)` wraps a call in a task's hooks at CALL time — the right shape for a CLI or a role module that is already running, where `withHooks` (which wraps at definition time) is the right shape for a gulp task. The guarantee is that each support role fires the hooks around its OWN model turn: `utils/diagnostics.js`, `utils/devteam.js` and `utils/manager.js` do, `diagnose.js` and `fix.js` fire none (a CLI cannot know whether its module is about to reach the model without repeating every refusal the module makes, and a container switch costs a model load). See docs/architecture.md "Pipeline hooks" and `hooks/README.md`. |
| `utils/qa-loop.js` | Shared QA-loop orchestration (a barrel over `utils/qa-loop/` — see the folder table below). **`runSharedQaLoop(cfg)`** runs the whole-installment validator → grader → feedback loop; **`runPerChapterQaLoop(cfg)`** runs the chapter-by-chapter version the four tasks fall back to when an installment is too large for one pass (per-chapter validator agents write partials → one findings-merge agent consolidates them into the task's standard report → the same tool-less grader → per-chapter author agents apply the chapter-tagged findings). Both share the grading half (`scoreAndConfirm`: the rolling window, the fail-closed unparseable-score handling, the per-iteration state persistence with the source fingerprint, the acceptance-criterion check, and the two cheap acceptances) and the agent-turn protocol (`runWriteTurn`), and both end the same two ways: a **no-op feedback stop** (it fingerprints the artifacts `cfg.feedbackArtifactFiles` names before and after the round and ends the loop when they are byte-identical, instead of paying for another validator round and another grade over an unchanged document) or the iteration budget, each under the `ON_QA_LIMIT` policy. Each task injects only its own stages — which agents to open, what they say, what each must leave on disk, its grader, and its log lines — plus `acceptedBy` / `limitReached` back onto its volume context. Also exports `confirmExceptionalScore` / `confirmPassingScore` (the exceptional-grade and passing-grade fast-accept paths — see docs/architecture.md "QA loop"), `validationReportRecoveryPrompt` (the validator recovery wording the tasks share so the fourth cannot drift), and `runVolumeWithModeFallback` — the whole-installment → chapter-by-chapter retry: it runs a volume's processing pass, and ONLY when that pass throws `isTooBigForOnePassError` does it wipe the attempt's outputs (`wipeAttemptOutputs`, including the rolling-state file, so the retry cannot inherit half a document or scores recorded for documents that no longer exist), flip `ctx.chunked`, and run the volume again — exactly once. A hang, a malformed tool call, a dead container, a missing previous artifact, a structural error or a bad ACCEPTANCE score do NOT trigger it (see gotcha 55). |
| `utils/series-run.js` | The plumbing every pipeline stage shares when it walks a series volume by volume: **`readRunArgs`** (the flags, read once — seven hand-written copies had already drifted, one reporting "No volume matching --volume null" for a merely empty manifest), **`openSeriesRun`** (the plan of record, the run's language settings, the volumes in reading order, narrowed for `--volume`), **`requirePreviousArtifacts`** (a cumulative volume cannot start when the volume it builds on is missing — `--dry-run` warns and continues, `ON_MISSING_PREVIOUS=skip` skips the volume, a real run fails loudly), **`volumeAlreadyAccepted`** (the idempotency skip: outputs exist AND the persisted acceptance state still passes, cancelled by `--force`, by the cumulative cascade, or by a changed source fingerprint), **`publishLatestToSeriesRoot`** (the series-current copy at the series root, taken from the last volume that holds a real document, never a scaffold stub; a `--volume` run does not publish), and **`runVolumeSeries`** (the walk itself, carrying the two guarantees no task may forget: a broken volume does not end the run under `ON_VOLUME_ERROR=skip` but a **structural** failure is never skippable, and a task that skipped volumes FAILS the run with a summary built under the task's own name — after its series-root publish, so the last good snapshot still reaches the root). Deliberately not a framework: no class, no lifecycle, no registration — each piece is a function a task calls where it needs it, so a task still reads top to bottom and its stage-specific decisions stay visible in the task. |

## The implementation folders

Each of these modules is a thin public face (`x.js`) that re-exports a folder of cohesive
modules (`x/`). Node resolves `x.js` before `x/`, so every `require("./x")`, every test, and
every test that monkey-patches the harness keeps working unchanged — but the logic lives in
the folder, so open the module that owns the behaviour you are changing instead of reading
the whole layer.
