# Conventions

How code, tests and prompt files are written in this repository.

Part of the ai-client documentation; the entry point is [AGENTS.md](../AGENTS.md).

## 11. Conventions



- **JSDoc on every function** (params + returns), with provenance comments where a behavior exists because of a live incident ("observed live: …"). New code without JSDoc is a review blocker. Use named types from `types.js` (e.g. `{GlossaryVolumeCtx}` instead of `{Object}`) — the type annotations enable IDE cross-references across files.
- **Update AGENTS.md after changes.** If your work adds, removes, or significantly modifies files, functions, or conventions, update this document to reflect the new state. Agents reading AGENTS.md should be able to rely on it as a current map of the codebase — not a stale one.
- Errors **fail loudly** with actionable messages (pointing at files, `.env` keys, or `.logs/`).
- Prompt files stay mode-agnostic; mode-specific text is appended in code (`AGENT_TOOLS_NOTE`), never forked into separate prompt files.

Cheap, precise, and the right tool for task logic — the task modules all call THROUGH the `harness` module object, so the patch applies. But it cuts the harness out: no provider, no streaming parser, no agent loop, no tool schemas, no approve gate, no retry, no truncation guard, no size tagging. (b) *Replace the model server*: `test/fake-backend.js`, and point `AI_BASE_URL` / `<ROLE>_BASE_URL` at it. Everything below the task code then runs for real, including the failure shapes (`backend.fail("truncated")`, `"tooBig"`, `"serverError"`, `"hang"`, …). Then read `test/prompt-audit.js` — it audits what the pipeline ASKED, not only what it produced, which is the half a green run cannot tell you: a run can pass every gate and still be answering a prompt that never contained the glossary.
- **A split module is one layer, and the layer's details are load-bearing.** When a module becomes a face over a folder: keep every exported name on the face; split along the `// ─── Section ───` banners the file already documents rather than a new idea of the seams; and give each submodule **its own** `require` for every builtin and sibling it uses — `node --check` cannot see a missing import, and this machine exposes `path` and `fs` as globals, so a submodule that forgets `require("path")` loads here and fails anywhere else. A relative require is re-resolved from the subfolder (`../harness` becomes `../../harness`, `./hooks` becomes `../hooks`), and a module's `ROOT = __dirname` becomes `projectRoot = path.join(__dirname, "..")`. Two checks catch what the syntax check cannot: scan every relative require for a target that actually exists, and run the suite — a slice boundary can quietly leave a dead copy of the function you meant to move. A suite that simulates "a fresh process" must forget the WHOLE layer (`dropModuleLayer` in `test/module-layer.js`): deleting only the face leaves the implementation's own state — the coefficients this process already measured — alive behind the reloaded face, and the test then asserts the wrong thing.
- **Grader calibration** (`test/calibration/` + `npm run calibrate`) — the quality system rests on a number a model produces, and this measures whether the number means anything. Six cases, each a short source text with a KNOWN defect in one translation (an omission, a meaning flip, a terminology break, a POV erasure + misattribution, an invented event, a quiet tense/duration drift) and a faithful rendering in the other. `test/calibrate.js` grades both with the PRODUCTION verifier (`gradeChapter` + `buildVerifyPrompt` + the production rubric and temperature — not an imitation of it) and reports, per case, the score, the band, and the gap, plus the distribution and the drift since the previous run. It exits non-zero when a grader ranks a known defect at or above the passing line, or cannot tell a flawed text from a faithful one. LIVE (it calls the `VERIFY_*` endpoint), so it is NOT part of `npm test`. The fixture is honest in both directions: the first run caught a real mistranslation in the fixture author's own "clean" text.
- Dependencies: AI SDK v6 + `@openharness/core` v0.7 + `jszip`/`cheerio` (epub extraction in `utils/source.js`); keep CommonJS, no new frameworks.
