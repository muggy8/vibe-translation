# The file map — the test suites

What each suite pins, and the guarantee it exists to keep. `npm test` runs them in this order, and the last one runs the whole pipeline against a scripted model.

Part of the ai-client documentation; the entry point is [AGENTS.md](../AGENTS.md).

## The file map — the test suites
| Path | Role |
|---|---|
| `test/test-glossary-load.js` | Pure tests (`npm test`): glossary helpers + the acceptance reply parsing contract (`parseAcceptanceReply` — JSON first, legacy integer fallback, garbage → `null`). |
| `test/test-translate.js` | Pure tests for the translation-stage helpers (`utils/translate.js`): `splitChapter`, `parseGlossaryTerms`, `extractStyleRules`, `checkTranslationQa` (incl. the per-pair residue / length-band / word-boundary matching), `residueRatio`, `isSpaceSeparated`, `lengthBands`, `buildPolishGuardFindings`, `mergeVolumeTranslation`, `stripMarkdownFence`, `tailOf`, `stripContinuityOverlap`, `runWithConcurrency`, `stageConcurrency`, `roleEndpoint`, `qaLoopDecision`, `qaMaxRounds`, **`planChapterSplit` (a chapter that fits is NOT split; which limit binds — feasibility vs admission vs an explicit `TRANSLATE_CHUNK_CHARS` override; no window/cap means it says so instead of inventing one; the character limit follows the text's own script mix; a thinking stage gets smaller parts), `translateChunkCap` (unset vs set vs the floor), `outputRatioFor` (table, scalar override, per-pair override, a malformed override is ignored), `measureOutputRatio` (only chapters with a draft count, the ratio is what the pipeline actually produced, an implausible one is clamped, no history → `null`) and `fitPromptBudget` (the chat wrapper is billed ONCE and reported, the same 52 `tokenBudgetFor` charges)**, plus the `assertWroteWithFallback` return-value contract (utils/fs.js). |
| `test/test-hooks.js` | Pure tests for the hook runner (`utils/hooks.js`), including the `TASKS` list (all eleven tasks + pipeline). |
| `test/test-postmortem.js` | The post-mortem and proof it has teeth (`npm test`). does NOT fall back on an ordinary error, a structural error, or when already chunked; both attempts failing reports BOTH), and the ANSWER side: `chunkSafetyFraction` is one implementation shared with `utils/source.js`, `artifactGrowthFactor` (default, override, a factor below 1 rejected), `answerRoom` (the estimate margin applied to the expected answer, an answer over the cap reported with a numeric shortfall, no cap configured → no invented limit), and `decideProcessingMode` on real temp files (it measures the previous volume's artifact as the floor for the answer, PRINTS the expected size, warns with the fix named when it does not fit the output cap — and its mode reason never cites the answer size, because chunking cannot repair that). |
| `test/test-intake.js` | Pure tests for the series intake (no AI, no network): epub fixtures built with jszip → `openEpub` (catalog card, series marker, spine sections, nav titles, **case-insensitive OPF tags**), `readEpubSection` bounded sampling, `htmlToPlainText` paragraph structure, `scriptCounts`, the epub tools (`epubInfo` / `readEpubText` cap / `stageVolume` idempotency + clobber refusal + path safety + **linking the book instead of duplicating it, and refusing to stage over a shortcut that points at a missing file — with "nothing was created at the path it pointed at" pinned**, see gotcha 77) and their approve gates (including the intake gate that shuts readFile/writeFile/grep at `.epub` paths — **on the argument each tool actually has**: `filePath` for the first two, `dirPath` for grep, see gotcha 60), `sanitizeFolderName`, `normalizeInstallmentNumber`, `filterVolumesByInstallment`, `validateManifest` (source-inside-its-folder, backslash normalization, per-volume `integrity` block required), `findDuplicateSources`, `validateVolumeIntegrity` (a missing block / non-boolean / out-of-range confidence / thin basis is rejected), `checkVolumeSourceShape` (too-thin epub, no-text archive, an art book — big image payload + thin prose — and the **illustrated-novel regression**: a book that is mostly image bytes with tiny front-matter sections and a book's worth of prose is NOT an art book, see gotcha 51; plus empty/short/binary text files) and `volumeIntegrityProblems` (a non-narrative volume is told to be excluded; a low-confidence one is flagged), `resolveRunSettings` precedence, `readCommittedLayout` + `applyCommittedLayout` (plan-of-record stability), `confidenceGate` (fail-closed), the deterministic `--dry-run` layout builder (committed folders recognised, no rival layout, **a shortcut recognised as the volume's staged book rather than re-staging the series beside itself**), the whole `getTranslationTarget()` run driven by a stubbed agent (plan validation/stamping/persisting, `.env` overrides, committed-folder protection, the confidence gate, the correction turn, manifest reuse, **an invalid/half-written cached manifest falling back to a fresh intake**, `--dry-run` previewing the committed plan, and the loud no-plan failure — tagged structural, because no plan of record means no step can run), and the **real-world packing fixture** (`buildPackedEpub`: anchored nav hrefs, image-only title pages, a chapter split across two files, landmarks-only entries) proving `extractEpubToBundle` groups it into real chapters with no phantom "empty in source" hole, plus the pure rules (`stripHrefFragment`, `groupSpineIntoChapters`, `classifySectionGroup`, `classifyNavEntry`, `titleOfUnnamedSection`, `stripRepeatedHeading`, `textCharsOf`) and the no-usable-contents-list fail-open (one chapter per page, loudly reported). |
| `test/test-qa-orchestration.js` | Offline orchestration tests (`npm test`) for the shared QA loops (`utils/qa-loop/whole.js` exercised through `character-voice.runVolume`, and `utils/qa-loop/chunked.js` driven directly): monkey-patches the harness (`runOneShot`, `createAgentHandle`, `createGatedFsTools`) and uses real temp files so the deterministic gates run unmodified.
