# The file map — the AI layer and the shared constants

The one door to the model, the constants every task imports, and the types they share.

Part of the ai-client documentation; the entry point is [AGENTS.md](../AGENTS.md).

## The file map — the AI layer and the shared constants
| Path | Role |
|---|---|
| `configs/shared.js` | The barrel for the run's shared configuration: the constants every task imports, re-exported from `configs/shared/` (folder table below). All nine task modules import from here; nothing but the barrel requires the folder files. It exists to break circular dependencies and end duplication — `AGENT_TOOLS_NOTE`, `PASSING_SCORE` and the run policies used to be copy-pasted into each task module, and the two boolean-env readers disagreed about what "off" meant. |
| `harness.js` | The AI layer: one-shot calls, agent handles, wiki tools, gated fs tools (**five tools: readFile / listFiles / grep / writeFile / editFile — `deleteFile` is not offered, and the gate refuses it anyway**, gotcha 8; with the read caps raised from the library defaults — `AGENT_MAX_LINE_LENGTH` / `AGENT_MAX_READ_BYTES`, see docs/architecture.md and gotcha 58 — and the **file-tool contract** applied to grep/listFiles/readFile: a folder where a model wrote a file, a filename ending where it wrote a wildcard, and an archive refused as text; see gotcha 60), **epub tools (`createEpubTools`: `epubInfo` / `readEpubText` / `stageVolume` + its own approve gate — the intake agent's senses, so it can open a book instead of guessing from its name; text comes back in bounded windows, staging is confined to the allowed dirs, never clobbers a different file, and LINKS the book into the volume folder rather than duplicating it — see gotcha 77)**, provider plumbing, run logging, the runaway-generation guard (aborts agent turns that produce excessive text without tool calls), **the truncation guard** (an agent turn that ends with `finish_reason=length` while its last step was a `writeFile`/`editFile` throws — a file written against the output-token cap is incomplete and would otherwise pass `assertWrote`; every `length` finish logs a greppable WARNING **through `logLine`, so it reaches `summary.log` and not only stderr** — gotcha 64), and the idle call deadline (`AI_CALL_DEADLINE_MS`, default 60 min — aborts a model call that makes no progress for that long; all fetch timeouts are disabled, so this is the only wall-clock bound on a call). **`createAgentHandle({contextManagement: true})` builds the uncapped, self-compacting turn** the delivery layer runs (docs/delivery-layer.md "Uncapped turns", gotcha 78): `agent.maxSteps` becomes the size of a CHUNK rather than of the turn, so between chunks the harness can move the turn's old read answers to disk (`utils/context.js`) and continue the SAME conversation; the handle gets `manage_context` / `recall_memory` added to whatever tool set it was handed; every tool result carries the working-window pressure line; a repeated identical call is stopped by the repetition detector; and **the library's own auto-compaction is switched OFF on every handle, managed or not** — a silent lossy summary is not a repair (gotcha 56). A handle WITHOUT `contextManagement` runs exactly one chunk, so every pipeline stage keeps its own step cap, its own step-cap warning, its own tool set, and no memory tools. Never bypass it to talk to the model. Multi-model support: per-call `endpoint` override (baseUrl/apiKey/model, falling back to `AI_*`), per-call `temperature` + sampling params (`topP/topK/minP/repetitionPenalty/presencePenalty`), the `hy-mt` thinking dialect (`no_think|low|high` → `reasoning_effort`), nullable `systemPrompt` (Hy-MT2's single-user-message contract), and `assertModelServing()` — a `GET /v1/models` control-plane check that fails loudly before a stage's first call (and logs the raw model list it got) — plus `measurePromptTokens()` — the token-calibration probe: one user message, `max_tokens: 1`, no system prompt, no thinking, and the server's own `usage.prompt_tokens` is the answer (an OpenAI-compatible server reports the prompt count only as part of a completion, and this machine's server has no `/tokenize` endpoint — probed: `/tokenize`, `/v1/tokenize`, `/api/tokenize`, `/num_tokens` all 404). `tagSizeOverflowError()` recognizes the server's own "prompt + max tokens exceeds the context" phrasings and tags the error as `tooBigForOnePassError`, so a task above can act on a SIZE failure without string-matching a server's error text (the two truncation guards above are tagged the same way). Logs every AI call to `.logs/<timestamp>/` — per-agent chat histories (system prompt, messages, assistant response, reasoning, tool calls) and one-shot call dumps — plus the summary log (greppable `CALL`/`RESULT`/`WARNING`/`[calibrate]` lines). |
| `research.js` | Client-side web research (Wikipedia Action API + optional Brave/Tavily/Serper). No LLM involved. |
| `types.js` | JSDoc type definitions shared across modules. Defines named typedefs (`TranslationTargetManifest`, `TranslationTargetVolume`, `TranslationTargetDiscovery`, `SourceSegment`, `SourceBundle`, `EpubMetadata`, `OpenedEpub`, `GlossaryVolumeCtx`, `WikiVolumeCtx`, `CharacterVoiceVolumeCtx`, `StyleGuideVolumeCtx`, `IMessage`, `EndpointOverride`, `RunOneShotCfg`, `CreateAgentHandleCfg`, `AgentHandle`, `Taps`, `FetchResult`, `WikiTools`, `ResearchNote`, `TranslationStateEntry`, `VerificationEntry`, `PolishVerificationEntry`, `VolumeReferences`, `HookContext`) that replace generic `{Object}` annotations in `@param`/`@returns` tags. Imported via `require("./types")` in every core module for IDE cross-reference resolution. Pure JSDoc — zero runtime side effects. |

## The implementation folders

Each of these modules is a thin public face (`x.js`) that re-exports a folder of cohesive
modules (`x/`). Node resolves `x.js` before `x/`, so every `require("./x")`, every test, and
every test that monkey-patches the harness keeps working unchanged — but the logic lives in
the folder, so open the module that owns the behaviour you are changing instead of reading
the whole layer.

### `configs/shared/` — the implementation of `configs/shared.js` (30 lines of face)

| File | Lines | What it owns |
| --- | --- | --- |
| `configs/shared/env.js` | 55 | The two readers every other knob is built from. `readBoolEnv(name, default)` is the one consistent boolean reader (on by default, off only for an explicit falsy value — the two historical AI_THINKING readers disagreed). `normalizePolicy(raw, allowed, default)` reads a choice knob and never throws, so a typo in .env degrades to the safe default instead of crashing the run or silently continuing. |
| `configs/shared/failures.js` | 138 | How a failure is classified, and why that decides everything downstream. `structuralError` / `isStructuralError` is the mark that overrides `ON_VOLUME_ERROR=skip` and `ON_TASK_ERROR=continue` — a source file that has gone missing is not a model that had a bad run. Its mirror `tooBigForOnePassError` / `isTooBigForOnePassError` is the ONLY failure the whole-installment → chapter-by-chapter fallback acts on (gotcha 55). `volumeFailureError(taskName, failed, total)` is the summary every task throws so a task that skipped volumes still fails the run (gotcha 21). |
| `configs/shared/acceptance.js` | 490 | The grading contract the four artifacts share: the window knobs (`ACCEPTANCE_WINDOW_SIZE`, `ACCEPTANCE_MIN_SAMPLES`, `PASSING_SCORE` — the one threshold every scored gate uses — `ACCEPTANCE_EXCEPTIONAL_SCORE`, `ACCEPTANCE_SCORE_TOLERANCE`, `ACCEPTANCE_SAMPLE_FLOOR`, `ACCEPTANCE_CONFIRMATION_CHECKS`, the derived `ACCEPTANCE_CONFIRMATION_MIN_SCORE`, and `ACCEPTANCE_CONFIRM_ON_PASSING` — "a grade that already passes earns the window's remaining samples by re-grading, not by rewriting") and the arithmetic over a window of grades (`computeRollingAverage`, `meetsAcceptanceCriteria`, `meetsExceptionalCriteria`, `isExceptionalScore`, `isAcceptedState`). Also the small JSON file that lets a re-run remember what a previous process already accepted: `saveRollingState` / `loadRollingState` (the state carries the run's `sourceFingerprint`, `acceptedBy` — `"rolling-window"` / `"exceptional-consensus"` / `"passing-consensus"` — the consensus confirmations, and `stalled`, the mark a QA loop writes when it stopped because a feedback pass applied nothing rather than because it ran out of iterations; see docs/architecture.md "QA loop") and `isSourceStale(state, bundle)` (fail-open when either side lacks a fingerprint). The broken `ACCEPTANCE_STRATEGY` / `ACCEPTANCE_BEST_MIN_PASSES` "best" alternative was removed — it could never accept at the default window. |
| `configs/shared/settings.js` | 268 | The run's shape — the file to open when asking "why did the run behave this way?". `AGENT_TOOLS_NOTE` (the prompt text that lives in exactly one place), `STAGE_CONCURRENCY` (the one worker-count knob for every stage), `judgeTemperature` / `judgeThinking` (every call that GRADES text samples calm, so a grader does not spend the reply budget thinking — gotcha 59; `utils/translate.js`'s `stageThinking()` delegates to it), the un-monitored run policies (`ON_VOLUME_ERROR`, `ON_MISSING_PREVIOUS`, `ON_QA_LIMIT`), `validateRequiredEnv({ dryRun })`, `DEFAULT_SOURCE_LANGUAGE` / `DEFAULT_TARGET_LANGUAGE`, `resolveRunSettings(manifest)` (.env override > manifest > default) and `seriesArtifactFile(name, legacyEnvKey, seriesDir)` — where a finished artifact is published, with the old per-file env names still honored. |

Read them in that order: settings (what the operator controls), acceptance (what a grade
means), failures (what may be skipped and what may not), env (how a knob is read).
