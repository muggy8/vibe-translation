# The file map — the AI layer and the shared constants

The one door to the model, the constants every task imports, and the types they share.

Part of the ai-client documentation; the entry point is [AGENTS.md](../AGENTS.md).

## The file map — the AI layer and the shared constants
| Path | Role |
|---|---|
| `configs/shared.js` | The barrel for the run's shared configuration: the constants every task imports, re-exported from `configs/shared/` (folder table below). Every task module imports from here — barrel or folder file, all ten pipeline steps' layers and the manual commands alike (the `extract` step's half that reads the run's policies is `extract/run.js`, not the face); nothing but the barrel requires the folder files. It exists to break circular dependencies and end duplication — `AGENT_TOOLS_NOTE`, `PASSING_SCORE` and the run policies used to be copy-pasted into each task module, and the two boolean-env readers disagreed about what "off" meant. |
| `configs/env-defaults.js` | The one setting a fresh clone does not have to set: `SERIES_LOCATION` defaults to the repo's own `epub_source/` folder (the default is absolute, it is announced when it is what got used, and an explicit value is left exactly as written). Called at the top of every entry point — gulpfile.js, index.js, get-translation-target.js and the ten task barrels — immediately after dotenv and **before any task module is required**, because several of them turn the variable into a constant at require time (AGENTS.md gotcha 79). `chosenSeriesLocation()` is the other half: the delivery layer (fix.js, diagnose.js, autopilot) refuses a folder it inherited from the default, because a manager / diagnosis / patch is an answer about ONE run. Those three still call `loadEnv()` at the top — .env loaded before any support module reads it, and quietly, because 77 modules call `dotenv.config()` themselves and v17 prints an advertising line per call. |
| `harness.js` | The AI layer: one-shot calls, agent handles, wiki tools, gated fs tools (**five tools: readFile / listFiles / grep / writeFile / editFile — `deleteFile` is not offered, and the gate refuses it anyway**, gotcha 8; with the read caps raised from the library defaults — `AGENT_MAX_LINE_LENGTH` / `AGENT_MAX_READ_BYTES`, see docs/architecture.md and gotcha 58 — and the **file-tool contract** applied to grep/listFiles/readFile: a folder where a model wrote a file, a filename ending where it wrote a wildcard, and an archive refused as text; see gotcha 60), **epub tools (`createEpubTools`: `epubInfo` / `readEpubText` / `stageVolume` + its own approve gate — the intake agent's senses, so it can open a book instead of guessing from its name; text comes back in bounded windows, staging is confined to the allowed dirs, never clobbers a different file, and LINKS the book into the volume folder rather than duplicating it — see gotcha 77)**, provider plumbing, run logging, the runaway-generation guard (aborts agent turns that produce excessive text without tool calls), **the truncation guard** (an agent turn that ends with `finish_reason=length` while its last step was a `writeFile`/`editFile` throws — a file written against the output-token cap is incomplete and would otherwise pass `assertWrote`; every `length` finish logs a greppable WARNING **through `logLine`, so it reaches `summary.log` and not only stderr** — gotcha 64), and the idle call deadline (`AI_CALL_DEADLINE_MS`, default 60 min — aborts a model call that makes no progress for that long; all fetch timeouts are disabled, so this is the only wall-clock bound on a call). **`createAgentHandle({contextManagement: true})` builds the uncapped, self-compacting turn** the delivery layer runs (docs/delivery-layer.md "Uncapped turns", gotcha 78): `agent.maxSteps` becomes the size of a CHUNK rather than of the turn, so between chunks the harness can move the turn's old read answers to disk (`utils/context.js`) and continue the SAME conversation; the handle gets `manage_context` / `recall_memory` added to whatever tool set it was handed; every tool result carries the working-window pressure line; a repeated identical call is stopped by the repetition detector; and **the library's own auto-compaction is switched OFF on every handle, managed or not** — a silent lossy summary is not a repair (gotcha 56). A handle WITHOUT `contextManagement` runs exactly one chunk, so every pipeline stage keeps its own step cap, its own step-cap warning, its own tool set, and no memory tools. Never bypass it to talk to the model. Multi-model support: per-call `endpoint` override (baseUrl/apiKey/model, falling back to `AI_*`), per-call `temperature` + sampling params (`topP/topK/minP/repetitionPenalty/presencePenalty`), the `hy-mt` and `index-mt` thinking dialects (`no_think|low|high` mapped to `reasoning_effort` for the first, to `chat_template_kwargs {enable_thinking: …}` for the second — the two translation models' chat templates read different variables, gotcha 83), nullable `systemPrompt` (the translation role's single-user-message contract), and `assertModelServing()` — a `GET /v1/models` control-plane check that fails loudly before a stage's first call (and logs the raw model list it got) — plus `measurePromptTokens()` — the token-calibration probe: one user message, `max_tokens: 1`, no system prompt, no thinking, and the server's own `usage.prompt_tokens` is the answer (an OpenAI-compatible server reports the prompt count only as part of a completion, and this machine's server has no `/tokenize` endpoint — probed: `/tokenize`, `/v1/tokenize`, `/api/tokenize`, `/num_tokens` all 404). `tagSizeOverflowError()` recognizes the server's own "prompt + max tokens exceeds the context" phrasings and tags the error as `tooBigForOnePassError`, so a task above can act on a SIZE failure without string-matching a server's error text (the two truncation guards above are tagged the same way). Logs every AI call to the run's `logs/` folder (`<SERIES_LOCATION>/.run/logs/<timestamp>/` — configs/run-state.js) — per-agent chat histories (system prompt, messages, assistant response, reasoning, tool calls) and one-shot call dumps — plus the summary log (greppable `CALL`/`RESULT`/`WARNING`/`[calibrate]` lines). |

| `extract.js` | **The `extract` pipeline step — slice 2 of `utils/source/plan/01-extraction-step.md`, and the only place in a run that asks "is the extracted text right?"** It walks the plan of record's volumes, resolves each one's bundle through the same `resolveSourceBundle` the other eleven callers use, runs `auditExtractedVolume`'s **six** deterministic checks over what came back, and writes the result: `extraction-<NN>.md` / `.json` per volume and `extraction-summary.md` / `.json` for the series, all under `postMortemDir()` and **nothing** in a volume folder. It **makes no model call** — no harness, no one-shot, no agent, no prompt file (pinned by a require-graph check in `test/test-extract-step.js`, and proved at the wire against the stub endpoint: 0 requests). It says per volume which of four things happened to that volume's bundle — **VERIFIED** (the cache matched the archive and schema 8, nothing re-extracted), **RE-EXTRACTED** (a cache was there and is no longer current), **EXTRACTED** (no cache existed), **READ** (a plain-text source has no cache to verify, and calling it "re-extracted" would be a lie about work that did not happen) — decided from `bundle.cacheHit` plus one fact the bundle layer cannot report afterwards: whether a `<base>-bundle.meta.json` was in the folder before the call (`extract/bundle-state.js`). **A HIGH finding fails the step with a `structuralError`, so `ON_TASK_ERROR=continue` cannot walk past a broken book; a MEDIUM is printed, counted and recorded, and the run continues.** It audits **every** volume before it fails, because the audit costs nothing and one run should answer "what is wrong with my books?" for all of them. Measured on the real corpus with `npm run pipeline -- --stages=extract`: `extract post-mortem — CLEAN (0 HIGH, 0 MEDIUM, 0 LOW, 36 expectation(s) checked)` — 17 volumes × 2 records + the summary pair, zero findings. Measured on the **real corpus** with `npx gulp extract`: 17 volumes, 133 chapters, 109 packaging groups, 2,450,415 characters, 45,429 pronunciation guides, 457 images, **0 HIGH and 0 MEDIUM**, **0 model calls**; the step's own reported time is **190 ms on a warm cache**, where all 17 print VERIFIED, against **2.2 s** for a cold pass measured on a copy whose extracted files had been deleted — and the cold and warm passes report the same 133 chapters and 45,429 guides, so the extraction is reproducible. Its one possible model call is not its own: `openSeriesRun` goes through the shared intake door, which runs the intake agent when the plan of record is missing or was generated for a different folder (gotcha 127). → `extract/`, `docs/map-core.md` §`extract/`, gotcha 127. |
| `extract-voice.js` | **Read one volume chapter by chapter and write its extraction output, and nothing else** — the reading half of the voice stage unbolted from the writing half. The voice stage used to pay twice: the extraction pass read the book and wrote `character-voice-new.json` (volume 01: ~1.1M tokens, healthy), and an author pass re-typed that notebook into `character-voice.md` (volume 01: 50M tokens, graded 48/100). That second half is gone — the stage now renders the reference out of the record instead of paying an agent to re-type it — and this command is what produced the notebook the render reads. `rebuild-voice.js` can already type the report from the notebook without a model, but until now the notebook could only be produced by running the expensive half beside it. This command is the reading half on its own: one call per chapter, in reading order, each chapter shown **the previous volume's published reference** (the constant previous-volume reference is what is shown, plus a bounded list of what this volume's own earlier chapters already produced — `prompts.js`'s `buildAlreadyExtractedNote`, because `chapterSegmentNote` asserts the cumulative material covers the earlier chapters and that assertion is only true of a pass that has been compiling). Each chapter's answer is written to its own `character-voice-extract-<chapter>.json` partial tagged with a fingerprint of the chapter text it came from, so an interrupted pass is finished by the next invocation **at no cost** and `--force` is the only way to pay for a chapter twice; the consolidated `character-voice-new.json` is written only when every chapter is in hand. It opens the volume's record through `openVoiceRecord` — the pipeline's own door — so copy-forward from the previous volume's sealed record, the glossary completeness rule and the roster fold all fire here exactly as they would in a run (measured on the real volume 02: 514 facts and 10 characters carried from volume 01, 34 glossary rows imported / 86 carried / 4 refused, and `俺` folded into 如月雨露 with 14 claims moved), and it files every claim through the same evidence rule. **It is not part of a run** — no stage requires it, it is not in `index.js`'s step list, and no environment variable turns any of its guards off — it never writes `character-voice.md` or `pov-map.md`, it seals nothing, and it refuses a volume whose record is already sealed (`extract-volume-sealed`), which is what keeps it out of volume 01. An unparseable chapter **refuses the pass** rather than dropping that chapter quietly, and a **cut-off** chapter — an answer whose array never reached its closing bracket, which is half an answer rather than a malformed one — is named, re-read once at the retry level (a constant, and on a machine whose `AI_THINKING_LEVEL` already equals it that is a same-level re-sample — gotcha 122), and kept as INCOMPLETE if it is still cut off; `--chapter=<id>` re-reads exactly one chapter by name and reuses every other chapter's partial for free, **and the answer it brings back replaces whatever that chapter's partial held, even when the old one held more claims** (measured on the real volume 02: ch1 111 → 51, ch5 78 → 53 — gotcha 122). The reading loop itself is `character-voice/reading.js`, shared with the stage itself, and this file is now the thin CLI over it (its exports are re-exports, so the suite that pins it is unchanged). See `docs/map-preproduction.md`, `character-voice/plan/04-implementation-plan.md` §7.9, gotcha 106 and gotcha 111. |

| `reopen-volume.js` | **Reopen one volume’s published reference record as a recorded act** (`npm run reopen -- --volume=NN --reason="…" [--cascade=retire]`). The act is **retire and re-derive**, never unseal: a row is written into `record_reopens` with the reason, `series.db` is moved whole to `series.db.retired-<stamp>`, the volume’s acceptance window (`character-voice-validation-rolling-state.json`) is moved aside with it, and a fresh record is opened carrying the reopen row so it knows it is a redo. It is not part of a run: no stage calls it, and the only way onto it is typing the command. | `attribute-voice.js` | **Ask, once per doubted roster entry, who is speaking the words a claim quotes** (`npm run attribute-voice -- --volume=NN [--check] [--dry-run] [--answers]`). Two halves, and only one of them costs anything. The **deterministic half** (`utils/reference-store/attribution.js`) reads the volume's own record and names every roster entry this volume filed claims under that this volume's own text does not measure as present — `--check` is that half alone, so it can be run against any volume in the series for free, and it writes nothing. The **reading half** (`character-voice/detective.js`) is the only part that asks the model anything: one pass per doubted entry, at most `DETECTIVE_MAX_GROUPS` per run, at most `DETECTIVE_MAX_STEPS` **read-only** tool calls each (the write tools are not offered at all), and `DETECTIVE_TOKEN_BUDGET` prompt tokens after which the remaining entries are reported as unanswered rather than paid for. An answer is filed in `attribution_answers`, so the next run can tell "nobody asked" from "somebody asked and agreed" and does not pay twice. An answer that **agrees** closes the question. An answer that **disagrees** opens one `challenge_fact` row per claim, owned by the asking volume, each with its own quote checked against the book — and the claim the reference already published is **not edited and not moved**: it is marked `disputed` and stays where it is until somebody closes the dispute with `resolve_challenge`. "The narrator said it" is a real answer and files its challenger with **no roster entry at all**, so the coverage rule never counts the narration as a character. What it does **not** do: it does not rewrite `character-voice.md` or `pov-map.md`, does not seal or unseal, does not file a `cast_alias` row even when the answer is "the name is printed in a spelling this record cannot see" (an alias changes how every later volume measures that character, which is the owner's decision, not an inference from one scene — the notebook names the door instead of walking through it), and does not widen how the record matches a name. | `release-translation.js` | **The only door past the freeze gate, and it is a recorded act rather than a switch.** Once a volume's `translation.md` and `translation-state.json` are on disk, the glossary, voice reference, style guide, wiki, audit and extracted text that translation was built from are frozen, and `utils/prereqs/freeze.js` refuses to rewrite them — with no flag, no environment variable, no ledger entry and no run policy on that refusal (AGENTS.md §4 rule 3). ## The implementation folders

Each of these modules is a thin public face (`x.js`) that re-exports a folder of cohesive
modules (`x/`). Node resolves `x.js` before `x/`, so every `require("./x")`, every test, and
every test that monkey-patches the harness keeps working unchanged — but the logic lives in
the folder, so open the module that owns the behaviour you are changing instead of reading
the whole layer.
